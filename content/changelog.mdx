# Changelog

All notable changes to the NFSFU234 ShotSweep Library will be documented in this file. The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/) and adheres to Semantic Versioning.

## [1.4.0] — Scroll capture, baselines and a stricter diff

### Added

* `--mode scroll`: capture a scroll-driven page as a series of viewport frames, one per scroll
  position, each taken once the page has stopped moving (scroll position first, then pixels).
  For pinned sections, GSAP ScrollTrigger scrubs, `animation-timeline: scroll()` and
  smooth-scroll libraries, where a full-page screenshot never plays the animation.
  * `--scroll-step <px|%>` sets the distance between frames (default half a viewport), or
    `--scroll-stop <px|%>` (repeatable) captures exactly the offsets you name; `100%` is the very bottom.
  * `--scroll-method <auto|native|wheel>`: `wheel` drives pages that hijack the mouse wheel;
    `auto` uses it only when nothing scrolls natively.
  * `--max-frames`, `--frame-delay` and `--settle-timeout` bound and tune the settling.
  * Frames are named by scroll offset (`scroll-y000450-1440x900.png`, `scroll-end-1440x900.png`),
    so `diff` compares the same moment of the animation on every run. Manifest entries record
    `scrollY` and `scrollMethod`, and `settled: false` for frames that never stopped changing.
* Every site folder now has its own `manifest.json` and `run-record.json` (paths relative to that
  folder), while the root keeps the complete manifest. A site folder can be copied or moved on its
  own and still be diffed or approved.
* `shotsweep approve <manifest> --to <dir>` promotes a run to be the new baseline. `--from-report`
  promotes only the pages a diff flagged, `--dry-run` previews, and every approval is appended to
  `approvals.json` with SHA-256 hashes. Failed captures are never promoted.
* `capture --mask <css>` (repeatable) and `--mask-color` paint over volatile elements (ads,
  timestamps, carousels) in `full`, `sections`, `element` and `scroll` captures.
* `diff --ignore x,y,w,h` (repeatable, or objects in the config file, optionally scoped to a URL),
  `--height-tolerance <px>` and `--pixel-threshold <0-1>` to cut false positives.
* `diff --fail-on-removed` and `--fail-on-added` to fail the run on pages present in only one run.
* `login --success-selector <css>` saves the session only if that element appears, and
  `--success-timeout` sets how long to wait. Without it, `login` warns when the password field is
  still showing after submit.
* `--browser <chromium|firefox|webkit>` on `capture` and `login`. The engine is recorded in
  `run-record.json`, and `diff` reports a change of engine as environment drift. Only Chromium is
  covered by the test suite; Firefox and WebKit need `npx playwright install firefox` (or `webkit`).
* `--describe` includes scroll-frame counts.

### Changed

* `diff` now treats a page that failed to capture in the new run as a regression
  (`capture-failed`). Before, it was reported as `removed`, which passes, so a failed capture could
  turn a CI check green. The newest attempt for a page decides, so a stale earlier screenshot in a
  merged manifest no longer hides a fresh failure.
* `--bearer` and `--header` are no longer sent to parent domains. `app.example.com` still shares
  credentials with its own subdomains and its `www.` twin, but a token for `app.team.vercel.app` no
  longer goes to `vercel.app`. Use `--headers-all-origins` if you need the old reach.
* `--resume` now works for `sections`, `element` and `scroll` jobs, not just `full`. A job is skipped only if
  its latest attempt succeeded and every file it wrote still exists.
* A warning that applies to a whole page is printed once per page, not once per screenshot.
* `run-record.json` records the real browser engine instead of always `chromium`.

### Fixed

* A 1px change in page height no longer has to be a hard failure; use `--height-tolerance`.
* `--password` on the command line now warns that it is visible in the process list.

See [Upgrading to 1.4](/docs/upgrading) for behaviour changes that can affect existing pipelines.

## [1.3.0] — Scroll-reveal capture and hardening

### Added

* Scroll warm-up before `full` and `sections` captures, so scroll-reveal content and lazy-loaded
  images appear. Disable with `--no-scroll`.
* `--image-wait <ms>`: wait for images still loading after the scroll, re-request images cancelled
  by a load timeout, and warn about any that never finish.
* A page that times out on `--wait-until` but is already usable is captured with a warning;
  `--strict-load` restores failing.
* `--freeze-animations`, `--user-agent`, `--ignore-https-errors`, and `--headers-all-origins`.
* URLs without a scheme get `https://` (`http://` for localhost), and pasted Markdown links are
  unwrapped. All invalid URLs are reported together before capture starts.
* Sitemap fetches have a timeout, a cycle guard, a depth limit, and `.xml.gz` support.
* Comments (`#`) and UTF-8 BOMs are handled in URL, paths and CSV files.
* Failure reasons and warnings are printed under the run summary.
* `diff` reports screenshots it can't read as `error` results.

### Changed

* `--bearer` and `--header` are sent only to the captured site and its subdomains.
* `manifest.json` entries are replaced per job, use forward-slash paths, and are written
  atomically. A corrupt manifest is moved aside instead of overwritten.
* Folder names include the port, and add a hash suffix for query-string, non-ASCII, or very long
  paths.
* Screenshots, `--wait` selectors and retries respect `--timeout`.
* `--resume` re-captures a job whose screenshot file was deleted.
* `diff` counts `error` results as regressions and matches pages across path styles, trailing
  slashes, and moved manifests.

### Fixed

* `--zip` with `--out .` no longer writes `..zip` or includes itself.
* A single failing page no longer aborts the whole batch, and Chromium is always closed.
* A broken `shotsweep.config.json` is reported instead of silently ignored.
* Malformed `--header` and `--cookie` values are rejected instead of skipped.
* Credentials embedded in URLs are masked in `run-record.json`.
* Stale `section-NN` files from an earlier run are removed.

See [Upgrading to 1.3](/docs/upgrading) for behaviour changes that can affect existing baselines.

## [1.2.0] — Element capture and run provenance

### Added

* `--mode element` with `--selector` to capture a single element, cropped to its own size.
* `run-record.json`, written with every capture (skip with `--no-record`): tool, browser and OS
  versions, redacted resolved config, and SHA-256 hashes of the screenshots.
* `diff` flags environment drift between two runs and records provenance, the pass/fail decision,
  and image hashes in `diff-report.json`.

## [0.1.0] — NFSFU234 Open Source Day (2026-08-25)

**Initial public release.**

NFSFU234 ShotSweep is a command-line screenshot and visual regression tool built for developers who need repeatable website captures, automated visual comparisons, CI-friendly workflows, and reliable screenshot automation at scale.

This is the first public release of ShotSweep and is being launched as part of **NFSFU234 Open Source Day**, alongside the established [NFSFU234 Tour Guide](https://tour-guide.nforshifu234dev.com/) and [NFSFU234 Form Validation](https://form-validation.nforshifu234dev.com/).

### Added

* Capture single URLs, arrays, CSVs, or complete sitemaps, including sitemap-index files.
* Full-page and section-sliced screenshot modes.
* Multiple viewport captures per run.
* Named viewport presets:

  * `desktop`
  * `tablet`
  * `mobile`
* Raw `WxH` viewport definitions.
* `--replace-origin` for reusing production sitemaps against localhost or staging environments.
* Generic authentication support:

  * saved sessions via `shotsweep login`
  * bearer tokens
  * custom headers
  * cookie injection
* Authentication workflows verified against real authenticated captures.
* `shotsweep diff` for pixel-comparing two capture runs by manifest.
* Diff output includes:

  * `old.png`
  * `new.png`
  * `diff.png`
  * `diff-report.json`
* `--zip` support for bundling diff output.
* Non-zero exit codes when real visual changes are detected, allowing ShotSweep to gate CI pipelines.
* `--concurrency` with CPU-aware warnings.
* `--timeout` and `--retries` for real-world capture reliability.
* Retry behavior verified against an actual transient failure.
* `--zip` support on `capture` for bundling capture output.
* `--dry-run` for previewing resolved targets without taking screenshots.
* `--json` and `--quiet` for scriptable and CI-friendly output.
* `--debug` for detailed diagnostic information.
* `--describe` for generating an AI-ready summary of a completed capture run.
* `--resume` for skipping URL/viewport pairs already captured in an existing output manifest.
* `--verbose` for persistent per-job completion output, particularly useful with concurrent captures.
* `--limit` and `--offset` for capturing a specific slice of resolved URLs.
* `--wait-until <domcontentloaded|load|networkidle>` for controlling when a page is considered ready for capture.
* `--threshold` supports:

  * raw ratios
  * percentages such as `"0.1%"`
  * named presets: `strict`, `default`, and `loose`
* Configuration file support through:

  * `shotsweep.config.json`
  * `.shotsweeprc.json`
* `shotsweep diff` reads the same configuration file as `capture`, with an optional `diff` section for diff-specific overrides.
* Explicit CLI flags take precedence over configuration-file values.
* CLI `name`, `description`, and `version` are now read from `package.json` at runtime rather than duplicated as hardcoded values.
* Per-file `manifest.json` logging including:

  * URL
  * mode
  * viewport
  * file path
  * file size
  * timestamp
