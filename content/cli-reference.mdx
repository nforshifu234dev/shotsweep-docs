# CLI reference

ShotSweep's CLI lets you capture screenshots, reuse authenticated sessions, compare capture runs for visual regressions, and approve a run as the new baseline. The reference below lists every command, flag, and default value, with examples for common workflows.

```text
shotsweep
│
├── capture
├── login
├── diff
└── approve
```

## `shotsweep capture`

Take screenshots of one or more pages.

**Input (pick one)**

| Flag | Description |
| --- | --- |
| `--url <url>` | Single URL to capture |
| `--urls <file>` | JSON array or newline-delimited file of URLs |
| `--csv <file>` | CSV file containing a column of URLs |
| `--csv-column <name>` | Column name in the CSV holding the URL (auto-detected if omitted) |
| `--sitemap <url>` | sitemap.xml URL to fetch and parse |
| `--base <url>` | Base URL to prepend to `--paths` |
| `--paths <file>` | JSON array or newline-delimited file of relative paths, used with `--base` |
| `--replace-origin <url>` | Rewrite every resolved URL's origin to this |
| `--limit <n>` | Capture at most this many resolved URLs (positive integer) |
| `--offset <n>` | Skip this many resolved URLs before capturing (`0` or more) |

URLs don't need a scheme: `example.com` becomes `https://example.com` (`http://` for
`localhost` and loopback addresses), and a pasted Markdown link such as
`[x](https://x.com)` is unwrapped. See [Inputs & Sitemaps](/docs/core-concepts/inputs#forgiving-urls).

**Capture behavior**

| Flag | Description | Default |
| --- | --- | --- |
| `--mode <mode>` | `full`, `sections`, `element` or `scroll` | `full` |
| `--selector <css>` | CSS selector of the single element to capture. **Required** with `--mode element` | — |
| `--browser <name>` | Browser engine: `chromium`, `firefox` or `webkit`. Firefox and WebKit need `npx playwright install <name>` first, and only Chromium is covered by ShotSweep's tests | `chromium` |
| `--viewport <WxH\|preset>` | Repeatable, e.g. `--viewport 1440x900` | `desktop` |
| `--wait-until <domcontentloaded\|load\|networkidle>` | What counts as "page loaded" before capturing | `load` |
| `--wait <ms\|selector>` | Wait a fixed ms or for a CSS selector, after `--wait-until` resolves. A selector that never appears is capped by `--timeout` and recorded as a warning | — |
| `--no-scroll` | Skip the top-to-bottom scroll that triggers scroll-reveal animations and lazy-loaded images | scroll is **on** for `full` and `sections` |
| `--image-wait <ms>` | After scrolling, how long to wait for images still loading. Unfinished images are reported as a warning | `10000` |
| `--strict-load` | Fail a page when `--wait-until` times out, instead of capturing it anyway with a warning | `false` |
| `--freeze-animations` | Fast-forward finite CSS animations and cancel infinite ones while capturing | `false` |
| `--user-agent <string>` | Present this User-Agent instead of headless Chromium's | — |
| `--ignore-https-errors` | Accept invalid or self-signed TLS certificates | `false` |
| `--dark` | Emulate `prefers-color-scheme: dark` | `false` |
| `--out <dir>` | Output directory | `./screenshots` |

**Scroll capture** (with `--mode scroll`, see [Scroll Capture](/docs/core-concepts/scroll-capture))

| Flag | Description | Default |
| --- | --- | --- |
| `--scroll-step <px\|%>` | Distance between frames, in pixels or as a percentage of the viewport height | `50%` |
| `--scroll-stop <px\|%>` | Repeatable. Capture exactly these offsets (pixels, or `N%` of the scrollable range) instead of an even step | — |
| `--scroll-method <auto\|native\|wheel>` | Scroll by the real scroll position, or by mouse-wheel events for pages that hijack the wheel | `auto` |
| `--max-frames <n>` | Upper bound on frames per page and viewport | `60` |
| `--frame-delay <ms>` | Minimum wait after each scroll before checking the frame has settled | `250` |
| `--settle-timeout <ms>` | How long to wait for a frame to stop changing before keeping it anyway (`0` disables) | `3000` |

**Volatile content**

| Flag | Description |
| --- | --- |
| `--mask <css>` | Repeatable. Paint over elements matching this selector (ads, timestamps, carousels) so they can't cause false diffs |
| `--mask-color <css>` | Colour of the mask boxes (default: Playwright's pink `#FF00FF`) |

**Auth**

| Flag | Description |
| --- | --- |
| `--session <file>` | Reuse a saved storageState session |
| `--bearer <token>` | Sets `Authorization: Bearer <token>` on requests to the captured site (and its subdomains) |
| `--header <"Key: Value">` | Repeatable, arbitrary request header, sent to the captured site only |
| `--headers-all-origins` | Send `--bearer` / `--header` values to **every** origin the page contacts, including third parties |
| `--cookie <"name=value; Domain=...">` | Repeatable cookie to inject (needs a `Domain=`; also accepts `Path=`, `Secure`, `HttpOnly`, `SameSite=`) |

**Reliability & recovery**

| Flag | Description | Default |
| --- | --- | --- |
| `--concurrency <n>` | Pages captured in parallel | `1` |
| `--timeout <ms>` | Timeout for each page load, selector wait and screenshot | `30000` |
| `--retries <n>` | Retry a failed page load this many times | `0` |
| `--resume` | Skip jobs (any mode) whose latest attempt in `--out`'s manifest succeeded and whose screenshot files all still exist | `false` |

**Output & scripting**

| Flag | Description | Default |
| --- | --- | --- |
| `--zip` | Also bundle the output directory into a `.zip` after capture | `false` |
| `--dry-run` | Resolve and print target URLs without capturing anything | `false` |
| `--json` | Print the final result as one JSON line instead of colored output | `false` |
| `--debug` | Show detailed diagnostic output while running | `false` |
| `--verbose` | Print one persistent line per completed job, instead of an overwriting spinner | `false` |
| `--quiet` | Suppress the live progress line | `false` |
| `--describe` | Print an AI-ready summary of the captured screenshots | `false` |
| `--no-record` | Skip writing `run-record.json` (tool, browser and OS versions, resolved config, artifact hashes), at the root and in each site folder. The manifests are still written | the record is written |

## `shotsweep login`

Drive a login form once and save the session for reuse with `capture --session`.

| Flag | Required | Description |
| --- | --- | --- |
| `--login-url <url>` | Yes | Page containing the login form |
| `--email-selector <css>` | Yes | CSS selector for the email/username field |
| `--password-selector <css>` | Yes | CSS selector for the password field |
| `--submit-selector <css>` | Yes | CSS selector for the submit button |
| `--email <value>` | No | Email/username (or set `SHOTSWEEP_EMAIL`) |
| `--password <value>` | No | Password (or set `SHOTSWEEP_PASSWORD`) |
| `--session-out <file>` | No | Where to save the session (default `./auth.json`) |
| `--success-selector <css>` | No | An element that only exists once logged in. The session is saved only if it appears |
| `--success-timeout <ms>` | No | How long to wait for `--success-selector` (default `10000`) |
| `--browser <name>` | No | Browser engine: `chromium` (default), `firefox` or `webkit` |

Prefer `SHOTSWEEP_PASSWORD` over `--password`: a flag is visible in the process list and shell history, and ShotSweep warns when you use it. See [Login Sessions](/docs/authentication/login-sessions).

## `shotsweep diff`

Compare two capture runs using their `manifest.json` files.

```bash filename="terminal"
shotsweep diff <old-manifest> <new-manifest>
```

| Flag | Description | Default |
| --- | --- | --- |
| `--out <dir>` | Where to write diff images and the report | `./diff` |
| `--threshold <ratio\|percent\|preset>` | Fraction of differing pixels before a page counts as changed — accepts `0.001`, `"0.1%"`, or `strict`/`default`/`loose` | `default` (`0.001`) |
| `--pixel-threshold <0-1>` | Per-pixel colour sensitivity. Lower is stricter | `0.1` |
| `--height-tolerance <px>` | Tolerate a height difference of up to N pixels (same width) by comparing the shared top region | `0` |
| `--ignore <x,y,w,h>` | Repeatable. Exclude a pixel region from comparison | — |
| `--fail-on-removed` | Fail when pages in the old run are missing from the new one | `false` |
| `--fail-on-added` | Fail when the new run contains pages that weren't in the old one | `false` |
| `--zip` | Also bundle the diff output into a `.zip` when done | `false` |
| `--json` | Print the summary as JSON instead of colored output | `false` |
| `--summary` | Print a human-readable visual regression summary | `false` |
| `--text <file>` | Write the human-readable summary to a text file | — |

See [Diffing Two Runs](/docs/visual-comparison/diff) for thresholds, regression
policy, reports, and exit-code behavior, and
[Reducing False Positives](/docs/visual-comparison/reducing-false-positives) for `--ignore`,
`--height-tolerance` and `--pixel-threshold`.

## `shotsweep approve`

Promote a reviewed run to be the new baseline.

```bash filename="terminal"
shotsweep approve <manifest> --to <dir>
```

| Flag | Description |
| --- | --- |
| `--to <dir>` | Baseline folder to write into (created if needed). **Required** |
| `--from-report <file>` | Only promote the pages this `diff-report.json` flagged as changed, resized or added |
| `--dry-run` | Show what would be promoted without copying anything |
| `--json` | Print the result as JSON |

Failed captures are never promoted, every approval is logged to `approvals.json`, and the command
exits non-zero if nothing was promoted. See [Approving Baselines](/docs/visual-comparison/baselines).

## Config file

Drop a `shotsweep.config.json` or `.shotsweeprc.json` in your project so `shotsweep capture`
and `shotsweep diff` run with fewer flags. For scroll capture the keys are camelCase: `scrollStep`, `scrollStop`, `scrollMethod`, `maxFrames`, `frameDelay`, `settleTimeout`.

```json filename="shotsweep.config.json"
{
  "sitemap": "https://example.com/sitemap.xml",
  "viewport": ["1440x900", "390x844"],
  "mode": "full",
  "out": "./screenshots",
  "diff": {
    "out": "./diff",
    "threshold": "loose",
    "summary": true,
    "text": "./reports/visual-summary.txt"
  }
}
```

Top-level keys are shared defaults for both commands. Repeatable options such as `viewport` accept
either a single string or an array.

A config file that exists but isn't valid JSON stops the run with an error naming the file, so a
typo never silently turns into default settings. Keys that don't match any option are reported as
warnings (on stderr) and ignored.

A `"diff"` sub-object overrides shared keys specifically for `shotsweep diff`.

Priority, highest to lowest:

**explicit CLI flag → command-specific config (`diff.*`) → shared top-level config**

For example, the config can provide the default threshold, output directory, summary, and text
report without requiring those flags every time.

An explicit CLI flag still wins:

```bash filename="terminal"
shotsweep diff \
  before/manifest.json \
  after/manifest.json \
  --threshold strict
```

Threshold values from a config file go through the same ratio, percentage, and preset
normalization as CLI values.

See [Diffing Two Runs](/docs/visual-comparison/diff#threshold).
