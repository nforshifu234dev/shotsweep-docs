# Login sessions

For apps behind a form login, `shotsweep login` drives the actual login form once in a real
browser and saves the resulting session (cookies and local storage) to disk.

```bash filename="terminal"
shotsweep login \
  --login-url https://example.com/login \
  --email-selector "#email" \
  --password-selector "#password" \
  --submit-selector "button[type=submit]" \
  --email you@example.com \
  --password $APP_PASSWORD \
  --session-out auth.json
```

Then reuse it on any capture run:

```bash filename="terminal"
shotsweep capture --sitemap https://example.com/sitemap.xml --session auth.json
```

```text
Login
  ↓
auth.json
  ↓
ShotSweep capture
  ↓
authenticated screenshots
```

## Required flags

`login` requires `--login-url`, `--email-selector`, `--password-selector`, and
`--submit-selector` — all four are CSS selectors ShotSweep uses to fill and submit the form.

## Confirm the login worked

Pass an element that only exists once you're logged in. The session is saved only if it appears, so
a wrong password can't silently produce a session that screenshots the login page for every URL:

```bash filename="terminal"
shotsweep login ... --success-selector "[data-testid=user-menu]" --success-timeout 15000
```

`--success-timeout` is how long to wait (default 10 seconds). Without `--success-selector`,
ShotSweep still warns when the password field is still visible on the same URL after submitting.

## Credentials from the environment

Instead of passing `--email` / `--password` on the command line, you can set:

```bash filename="terminal"
export SHOTSWEEP_EMAIL=you@example.com
export SHOTSWEEP_PASSWORD=your-password
```

Prefer the environment variables to `--password`: a flag is visible in the process list and your
shell history, and ShotSweep warns when you use it.

`shotsweep login` saves the file readable by your user only (on macOS and Linux).

`login` also accepts `--browser <chromium|firefox|webkit>`, so the session is made in the same engine
you capture with.

## Don't commit your session file

`auth.json` contains real cookies and storage state for an authenticated account. Treat it like a
credential:

- add it to `.gitignore`
- don't commit it, even to a private repo
- regenerate it if it ever leaks
